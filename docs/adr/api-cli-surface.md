Granularity note: this is the wayfinding-level surface ADR. It fixes the version promise, the freeze semantics, the verb taxonomy with its closed v1 set (one declared join point: #28's adapter verbs), the resolution and output rules, and the split of duties. The endpoint-by-endpoint enumeration is the OpenAPI document itself — produced at implementation, validated against this ADR's rules by the CI layers #22 fixes. > **Amends the machine-identity ADR ([machine-identities.md](./machine-identities.md), [#17](https://github.com/Dunky13/envweave/issues/17)), two declared parts.** #17 fixes the token-emission discipline as TTY / `--output-file` (`O_EXCL`, `0600`) / an explicit print flag it spells `--print-token`. **(1)** This ADR generalizes that triad into the universal grammar for *every* plaintext-emitting print path (§ Output grammar) and renames the explicit-print leg uniformly to **`--dangerously-print`** — one flag name across token mint, `values export`, `values get` and every future disclosure verb, so "dangerous" is readable in every CI log and shell history where the flag appears. **(2)** The TTY leg's *mechanism* changes: #17 permitted plaintext to ordinary stdout when stdout is a TTY, but the Compose ADR's own locked finding — a PTY is allocatable by CI runners, `script`, tmux and service managers; `isatty()` proves neither presence nor intent (#18 § Credential separation) — applies to output exactly as it applied to input. Under this ADR, **plaintext never goes to stdout without `--dangerously-print`, TTY or not**; the interactive path writes to the **controlling terminal** (`/dev/tty`; `CONOUT$` on Windows) after an in-terminal confirmation, which a log-capturing pipe does not receive. Refusal behaviour and the no-secret-on-argv rule are unchanged.

## Version promise — `/api/v1`, additive-only after the freeze

The API lives under a **URL version prefix `/api/v1`**. The promise:

- **Pre-freeze** (implementation period): the spec may change freely, including breaking changes. Nothing outside the repo may depend on it.
- **The freeze is the first stable release**: the first non-prerelease SemVer tag (`v1.0.0`, not `v1.0.0-rc.*` — prerelease tags freeze nothing). From that tag onward, changes to `/api/v1` are **additive-only**: new endpoints, new *optional* request fields, new response fields (clients must ignore unknown fields — stated in the spec). Enums that may grow are declared **open at freeze time** via a pinned `x-extensible-enum`-style extension, and all three generated consumers (Go server types, Go client, TS/Zod client) must preserve and tolerate unknown values for open enums — closed enums never grow. Anything breaking requires `/api/v2` — **which v1 explicitly does not plan**; the prefix exists so a future break has somewhere to go other than a flag-day.
- **The promise covers behaviour, not just shapes.** A frozen operation's authorization formula, side effects, idempotency and error semantics are part of the contract: the spec records the formula and semantics per operation (description-level, reviewed like code), and changing them post-freeze is a breaking change even when the schema diff is empty. OpenAPI diffing cannot police this — review of `api/openapi.yaml` changes against this rule does, which is why the spec is hand-written and reviewed (#22).
- **Skew guarantee, both directions:** an old client against a new server works within the major (additive-only + open-enum tolerance), verified by a CI job that runs the **freeze-tag generated client against the current server** in the contract-test harness. A new client against an old server degrades loudly, not silently: the spec carries a **per-operation minimum API revision**, generated into clients as a capability registry; the CLI compares it against the server's advertised revision (§ meta) and refuses unsupported verbs naming the server version — a bare version string is not the mechanism, the registry is.
- **The freeze is a CI invariant, not a doc sentence:** once the freeze tag exists, the pipeline diffs `api/openapi.yaml` against the immutable freeze commit using a full structural diff (oasdiff, pinned), **fail-closed over an allowlist of permitted addition change-types**: any change ID not on the allowlist — including oasdiff classifications below "breaking", and change IDs introduced by future oasdiff versions — is a red build. oasdiff's own severity taxonomy is explicitly *not* the policy (it classes some forbidden changes as warning/info — e.g. removals after deprecation windows this promise does not offer). Negative fixtures pin the gate: deleting a deprecated endpoint, removing a response-enum value, and removing a security requirement must each fail in CI, permanently.
- **A meta endpoint ships inside the spec** (`/api/v1/meta`), unauthenticated, response frozen as an **exact closed allowlist: server version, API revision, and protocol capabilities** (which authentication protocol flows this instance serves — needed by `login` before any session exists). Nothing tenant- or configuration-shaped: instance capability discovery beyond protocol selection happens after authentication. The endpoint sits under #16's instance-wide pre-auth admission limits like every other pre-auth path, and its response shape is contract-tested.

The **ESO-provider extension path (#19) waits on exactly this freeze** — the first stable release — nothing else.

*Rejected:* header/media-type versioning (invisible to curl and logs — hostile to the operator audience #22 privileges); no prefix + SemVer-only (leaves "additive-only" with no enforcement anchor and a future break with no home); date-based versions (implies a cadence of breaks this project does not intend); trusting oasdiff's default breaking-only gate (fails open on warning-classed removals).

### The CLI is a frozen surface too

Scripts are clients. From the same first stable release, within the major: **no verb or flag is removed or repurposed**; `-o json` output schemas are additive-only (same unknown-field rule as the API); exit-code meanings (§ Output grammar) are stable; `--format` values are never removed. Enforced by golden snapshots in CI: help output, machine-output schemas, and exit codes for a fixed scenario matrix are committed fixtures whose diff is reviewed like a spec change. Human-oriented `table` output is explicitly *not* frozen — scripts that parse tables instead of `-o json` are outside the promise, stated in the docs.

## One surface — no client-special domain endpoints

**The embedded SPA consumes `/api/v1` exactly as the CLI and operator do.** Same spec, same contract tests, same unauthorized ≡ nonexistent behaviour. #19's integration-neutrality rule ("no operator-special endpoints") generalizes across the **domain surface** — every resource, fetch, manifest, cursor and projection endpoint serves every client identically; what differs per client is the **authentication artifact** — browser session cookie, CLI session, machine credential (#16/#17) — never the domain surface.

Consequences, which are the point:

- **The parity principle (below) is structurally enforced.** A UI feature cannot exist without a public endpoint; UI-only API drift is impossible by construction, not by review vigilance.
- The freeze protects the SPA identically — the SPA is just another versioned client shipping in the same artifact.
- Every domain authorization path is spec-visible and contract-tested; there is no "internal" route where the chokepoint discipline (#23) escapes the response-shape assertions.

**The honest exception, stated as a closed class rather than hand-waved:** **authentication-protocol endpoints are client-specific by nature** — an OIDC callback is meaningless to curl, the CLI handoff endpoints are meaningless to the SPA. They form a **closed, enumerated, versioned exception set** inside the spec: login flows, WebAuthn ceremony endpoints (registration/assertion options and results), OIDC redirect/callback, session refresh, CLI loopback-handoff and device-flow endpoints (§ Login transports). They live under `/api/v1`, are contract-tested, carry their own threat requirements (#16's transaction rules, pre-auth admission limits, this ADR's transport rules) — but the no-client-special rule binds the *domain* surface, and this set is the only place it does not. A new endpoint claiming membership in the exception set is a spec review event, not a convenience.

Serving the SPA shell itself (static assets under the route partitioning #22 fixes) is not API and carries no authority.

*Rejected:* `/api/internal` for UI-only concerns — every internal endpoint is an unfrozen, un-contract-tested authorization path, exactly where chokepoint discipline erodes.

**Semantics inherit locked ADRs unchanged — the CLI re-implements no policy:**

- `values diff` between environments follows #11's oracle rules exactly: secret keys show **write-presence signals only** without the reveal gate; full value diffs require the gate — `read ∧ reveal` for the current side, `read ∧ reveal-history` for any historical side (§ Output grammar fixes the formulas) — with the same per-key audit events as the UI.
- `revision rollback` and every protected-environment mutation run **the same enumerated-key ceremony** as the UI (#21): the CLI initiates, the ceremony's reauth happens per § Login transports, the blocked-env veto and least-blast semantics (#11) apply identically.
- `audit query`/`export` are proof-scoped `audit-read` operations, themselves audited, per #24 — the CLI adds transport, not semantics.

### Authentication-artifact eligibility — the verb × artifact matrix

Two artifact families exist (#16/#17): human sessions (browser or CLI) and machine credentials. **Every verb declares its eligible set in the spec, as a closed matrix**; the classes are fixed here:

- **Machine-only:** `run`, `compose render`, `compose sync` accept **only machine credentials** (#18's locked separation), with #18's **single narrow exception restated exactly**: `run` — and only `run` — may use a human session when *all* of `--use-human-session`, stderr-is-a-TTY (an additional refusal, never the control), the enumerated environment/key-set confirmation, and the bound reauth ceremony hold. `render` and `sync` have **no human path**.
- **Machine-eligible (automation):** `definitions check/plan/apply`, `key` mutations, `values export` (workload/automation `read`; `reveal` by explicit opt-in — #17/#18), `audit export`/`query` (automation `audit-read` — #24) — per #15's automation allowlist (`edit`/`publish`/`definitions-edit`), which is what makes the #13 CI plan/apply pipeline possible at all.
- **Human-only:** `adopt`, `scaffold`, **`values import`**, `login` (#18's locked list); everything under `manage-*` and account authority — `sa` group, access group, account group, org/project lifecycle, `backup`, crypto ops (#15: machine allowlists never include `manage-*`; `backup-export` and rotation are grants held by operator humans, #23).
- **Local-only:** the local admin group (§ Responsibility split) — neither artifact; local host authority.

**Selection is explicit when ambient artifacts collide.** Resolution: `--auth=human|machine` flag wins; else if exactly one eligible artifact is present for the resolved instance, it is used; **if both a human session and a machine credential are present and the verb admits both, the CLI hard-fails** naming both artifacts and requiring `--auth` — a stale `ENVWEAVE_TOKEN` must never silently replace the expected human session, which would both skip the ceremony and misattribute the audit trail. The resolved artifact (kind + principal) is part of the disclosure echo (§ Context model).

### The parity principle

**Every server-mediated capability is reachable from both the CLI and the UI in v1.** Neither surface is the "advanced" one. Honest scope: client-local delivery operations (`render`, `run`, `adopt`, `doctor`, snapshot handling) are CLI-only *by nature* — they act on the box the CLI runs on; the operator's reconciliation is K8s-only likewise; the local-admin class is deliberately reachable from neither remote surface. Parity binds the server-mediated set, and the one-surface rule (above) enforces it structurally in the UI→CLI direction; this principle states it normatively in both. The UI prototypes (#29/#30/#31) and the spec inherit it as a review criterion: a screen without an endpoint, or an endpoint without a UI surface, is a finding — either a parity defect, or (for genuinely client-local, local-only, or auth-protocol paths) a documented exemption in the spec's closed exemption list. "We didn't get to the UI" is not an exemption.

## Context model — explicit-first, no persistent selection

A disclosure verb aimed at the wrong environment is a wrong-env plaintext export, so *which instance/org/project/env a command targets* is a safety property — and *which server receives a credential* is a bigger one.

**Instance trust is separate from, and prior to, context resolution.** The instance set is a **local trust store** recording, per instance, the canonical origin (scheme, host, port) and the **expected certificate identity (SPKI/CA pin) captured at establishment**. Session artifacts and every stored credential reference are **bound to that recorded origin**: the CLI presents a credential only to the origin it was established against, never follows a redirect off-origin with a credential, and verifies the pinned identity on connect. An instance enters the store by exactly two acts, neither of which repository content can perform:

- **Interactive establishment** — `login <url>` or `context create --instance <url>` **require an interactive terminal and display the origin plus its certificate fingerprint for explicit confirmation before recording**; both **refuse non-TTY invocation outright**. There is no silent trust-on-first-use.
- **Provisioned establishment (the CI path)** — trust is **imported, never bootstrapped**: a trust bundle (canonical origin + SPKI/CA pin) supplied via `--trust-file` or `ENVWEAVE_TRUST_BUNDLE`, provisioned through the **same protected out-of-repository channel as the credential itself** (the CI secret store, the K8s Secret, the config-management vault). The CLI presents a machine credential **only** to the origin named by its paired trust bundle. The security argument is alignment of channels: an attacker who cannot read the secret store cannot redirect the credential, and an attacker who can read it already holds the credential — the trust material adds no new capability to either.

**A repository file can never introduce or establish an origin — not directly, and not by invoking establishment.** The pin file (below) names an instance by *reference*; if the reference is not in the local trust store, the CLI refuses and names the missing provisioning step — it does not prompt-to-trust mid-command, and it never sends any credential (session or `--token-file`/`ENVWEAVE_TOKEN` material) toward an origin whose trust did not arrive through one of the two acts above. Without this rule, a malicious repo's pin file (or a repo-invoked raw `context create`) plus an ambient CI token is a bearer-token exfiltration: the token ships to an attacker's validly-certificated HTTPS server before Envweave authorization is ever evaluated — the same hostile-server class #19 closed for the operator by making the instance URL cluster-scoped and immutable, closed here by making trust material travel in the credential's own protected channel.

Target resolution, per dimension, first hit wins:

1. **Flags** — `--context`, `--instance`, `--org`, `--project`, `--env`.
2. **Environment variables** — `ENVWEAVE_CONTEXT`, `ENVWEAVE_INSTANCE`, `ENVWEAVE_ORG`, `ENVWEAVE_PROJECT`, `ENVWEAVE_ENV`.
3. **Project-dir pin file** — a committable, non-secret file at the repo/directory root naming an instance *reference* plus org, project (and optionally env): the `.nvmrc` of Envweave, natural in Compose repos. Never credentials, never an origin (names and a trust-store reference — documentation-class, like #13's bundles).
4. **Named contexts** — stored tuples (instance reference + org/project/env), created and listed explicitly, stored in the XDG state directory under #22's protection model. **Selected per invocation only** — `--context` or shell-scoped `ENVWEAVE_CONTEXT`. There is **no persistent "active context"**: an earlier draft's `context use` was the sticky global this section prohibits, wearing a different name — one forgotten `use` before a disclosure verb is the wrong-env export this model exists to prevent. (`context use` does not exist; the verb set has `create/list/show/delete`.)

Rules with teeth:

- **One coherent tuple, validated before action.** After per-dimension resolution, the assembled target must resolve server-side to a single consistent chain — names bind to immutable ids within their parent (env within project within org, #7/#23); a Frankenstein tuple spliced from unrelated sources that names no real chain is a hard error before any operation. Overriding one dimension (e.g. `--env staging` against a pinned project) is legitimate exactly because the override re-resolves within the same validated chain.
- **Ambiguity is a hard error, never a default.** No dimension is ever silently assumed; a command missing a required dimension after resolution fails, naming what was missing and where it looked (fail-fast, no silent fallbacks).
- **Disclosure-class commands echo the fully resolved target to stderr before acting** — instance origin, org/project/env **with their resolved immutable ids**, which precedence level supplied each dimension, and the selected authentication artifact (kind + principal). The active target is visible exactly when it matters, without polluting parseable stdout.
- **`login <instance-url>` stores per-instance CLI session artifacts** (#16); multiple instances coexist; contexts name which one they bind. Artifacts live under the XDG state directory, `0700`/`0600`, `doctor`-verified (#22).

## Output grammar — two closed classes, the print triad, masked defaults, no secrets on argv

Every CLI path that handles secret plaintext belongs to exactly one of **two exhaustive classes, fixed here** — a new verb cannot self-classify to escape either:

- **Delivery operations** (closed list: `run --`, `compose render`, `compose sync`, snapshot handling): plaintext flows to the destination, atomicity, authorization and audit rules their locked ADR fixes (#18 — rendering *is* a `values export` and carries its full formula; generation directories, stamps, tmpfs rules unchanged). Nothing is printed. `run --` **`exec`s the child** (#18): after a successful exec there is no Envweave process — the child's exit status and signal disposition are the invocation's, untouched.
- **Print operations** (everything else that can emit plaintext: `values get`, `values export` to output, `sa credential mint`, ceremony-gated `revision show`, …): governed by the **print triad**. Plaintext goes to exactly one of:
  - **(a)** the **controlling terminal** (`/dev/tty`; `CONOUT$` on Windows), after an in-terminal confirmation — never ordinary stdout, even when stdout is a TTY: a PTY is allocatable by CI runners, `script`, tmux and service managers, and `isatty()` proves neither presence nor intent (#18's locked finding, applied to output — declared amendment 2 to #17);
  - **(b)** a file created by the CLI via `--output-file`: the parent directory is opened first (`O_DIRECTORY|O_NOFOLLOW`) and checked — owned by the invoking user, not world-writable — then the final component is created relative to that dirfd via `openat(O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW)`, `fchmod` to exactly `0600` (umask-independent), and `fstat` on the written descriptor confirming a regular file; on Windows, `CREATE_NEW` plus an owner-only DACL. Symlinked or shared-writable parents are refused by these checks, not delegated to caller judgment; ancestry *above* the checked parent remains the caller's path choice, stated in docs;
  - **(c)** stdout, **only** under the explicit **`--dangerously-print`** flag;
  - and is **refused otherwise**, naming the three options.

- **Masked by default.** Browse and read verbs never emit secret values — `key list` shows names, classification, presence; `revision list`/`show` follow #11's write-presence rules. `config`-classified values are readable under `read` alone (#15: classification *is* the boundary); `secret` plaintext flows only through an explicit reveal-gated verb.
- **`values export` is the one bulk-disclosure verb.** Its gates are the locked formulas and nothing else, stated separately because the capabilities imply nothing about each other (#15): **current material: `read(E)` ∧ `reveal(E)`; historical/pinned material: `read(E)` ∧ `reveal-history(E)`** — a mixed export evaluates each formula over exactly the material it governs (#15/#18). **No admin gate, no new capability** — "export needs an admin token" was considered and rejected as a second permission language (#15: authority is grants; `admin` is a template that expands into grants, not a checkable property). The human-session ceremony applies per #18: explicit flag + **the ceremony enumerates the full key set the export covers** + bound reauth; a machine principal with the machine-`reveal` opt-in (#17) exports without ceremony — that is CI render, by design. One audit event per disclosed key (#15), never "exported N secrets".
- **No secrets on argv, either direction.** Generalizing #17's no-`--token`-flag rule: no verb accepts a secret value as an argument or flag value. `values set` accepts a **no-echo terminal prompt, stdin, or an explicitly named existing input file** — **never an external editor for `secret` values in v1**: editors persist swap, backup, undo and crash-recovery copies (and run plugins) outside Envweave's permission control, an unbounded plaintext residue the triad exists to prevent. Editor-assisted editing remains available for `config` values. Nothing secret transits `ps`, `/proc/*/cmdline`, or shell history, inbound or outbound.
- **Machine-readable output is per-verb, not one global switch.** General verbs take `-o table|json` (`table` default, deterministic regardless of TTY — scripts opt in to `json` explicitly; `json` shapes are generated from the same OpenAPI spec as the client types — one contract, all consumers). Verbs with a locked format keep it, spelled as their ADR fixed: **`audit export` emits JSONL** (#24, fixed, not switchable); **`values export --format dotenv|json`** (#13's spelling — `--format` names the *payload encoding* on export paths, `-o` names the *envelope* on browse paths; both stated in the spec); `definitions export` emits the canonical bundle encoding (#13). `values get --raw` prints a single scalar for composition; raw and every export format obey the print triad.
- **Deterministic exit codes**, fixed as a closed set **scoped to Envweave's own termination**: `0` success; `1` internal/unexpected; `2` usage; `3` authentication required or failed; `4` refused (validation, policy, ceremony declined, trust-store refusal, output-grammar refusal); `5` not found — **which is also unauthorized**, indistinguishable by design (#15: unauthorized ≡ nonexistent must hold on the CLI exactly as on the wire); `6` server/transport unavailable; `126`/`127` for `run --` launch failures per POSIX convention (found-but-not-executable / not-found). **After a successful `run --` exec the child owns the status** — the closed set applies only before exec succeeds. Scripts branch on codes, not on parsing error prose.
- The context echo (§ above) and all diagnostics go to **stderr**; stdout carries only the requested payload, so `-o json` output is parseable by construction.

## Login and reauth transports

#16 fixes *what* (CLI sessions as a distinct artifact; local floor never disableable; reauth = possession factor dispatched by how the session authenticated; protected/effective-`0` windows require WebAuthn — TOTP provably cannot honour `0`). This section fixes *how a terminal performs it*:

- **`login` — browser handoff primary, RFC 8252 shape.** The CLI binds a listener on a **loopback IP literal** (`127.0.0.1`/`::1`, ephemeral port, loopback-only, no `SO_REUSEADDR`/`SO_REUSEPORT`), opens the instance's login page with the exact redirect URI and a high-entropy single-use state, and the browser completes **any** supported method — OIDC, local password, WebAuthn — under #16's server-side transaction with binding purpose. **The callback carries only a single-use authorization code plus the state — never the session artifact**: a bearer in the front channel violates the threat model's no-secrets-in-URLs baseline and is interceptable at the callback. The CLI validates state and exact redirect match, closes the listener immediately, then **redeems the code over TLS on the back channel with a PKCE-style proof bound to the initiating CLI's ephemeral key** — an intercepted code without the verifier redeems nothing. The CLI never sees OIDC tokens or the password. These invariants are normative here, not deferred to the spec; concrete lifetimes → #32.
- **Device-code fallback (`login --device`) for SSH/headless human sessions, RFC 8628 adopted normatively:** distinct high-entropy `device_code` (never displayed) and short human `user_code`; server-directed polling interval with `slow_down`; single consumption; rate-limited user-code entry under #16's pre-auth admission limits; and the approval page **names the code, the client class (CLI), the instance, the purpose, and the session type being created** — explicit approval, no auto-consent. Second choice, not primary: a code typed cross-device has no origin binding, a phishing-surface cost the loopback flow doesn't pay; the spec states the trade-off and the flow's bounded lifetime.
- **Terminal-native local login** (`login --local`): password + TOTP prompted in-terminal (no-echo, never argv). Exists because the local floor must work with no browser on the box at all; WebAuthn is structurally unavailable in this path, so accounts under a WebAuthn-requiring policy complete login via handoff or device flow instead — refused loudly, naming the reason.
- **Reauth ceremonies** (#21) from the CLI **dispatch by how the current session authenticated and what is enrolled — #16's rules, not a CLI-invented matrix**: local-account sessions may satisfy a window > `0` with inline terminal TOTP where #16 permits TOTP; WebAuthn reauth (including every protected/effective-`0` case) goes through **browser handoff to the same purpose-bound, enumerated-key-set ceremony the UI uses** (#21) — one ceremony implementation, the CLI borrowing it, with the handoff carrying the ceremony's binding purpose so an induced login round-trip cannot satisfy it (#16); OIDC-authenticated sessions reauth by **re-running the OIDC transaction** with the same identity under #16's `auth_time`/`acr`/`amr` requirements, via the same handoff. The CLI names the reason before opening the browser; the enumerated key set is displayed in the ceremony.
- **FIDO2 security keys direct-in-terminal**: recorded as a **named post-v1 candidate**, not promised (→ #26). Doing it in v1 means hand-integrating the hardest auth surface against the no-hand-rolled-primitive invariant's spirit (#16) for a niche win over the handoff.
- Machine principals never do any of this: credentials/federation per #17, no interactive flows, no ceremonies (machines do not reauthenticate — #15/#17).

## Responsibility split

- **Server**: all **network-reachable domain authority**. Authorization (every formula, in-transaction, at the chokepoint — #23), audit, crypto, validation, publishing, session management, ceremony evaluation. No remote client ever evaluates policy.
- **The closed local-authority exception set — no new members.** #23 fixes `SystemProof` as the closed no-principal set {boot, migrate, recovery reconciliation, break-glass}; #15 makes break-glass local host authority with **no HTTP endpoint**. The local-admin verbs are those members' existing surfaces, not additions: `init` and `admin create` are the boot/bootstrap member (#14's key generation, #16's bootstrap seeding); `migrate` is the migrate member (#22); `restore reconcile` is recovery reconciliation; `break-glass` is break-glass. They act **on the server's own host against local state, never over the network API**, under the mint-site-bound `SystemProof` discipline #23 fixes. `instance-config` is **not** in this class — it is a grant-evaluated `InstanceProof` operation over the network path (#23/#24), like the crypto ops. And none of this touches #22's multicall mode set: local-admin verbs are **client verbs of the same binary executed on the server host**, not new modes — the mode set (`server`/`operator`/`migrate`/client) is unchanged.
- **Operator**: K8s reconciliation only (#19) — CR-driven, per-CR identity, no Envweave credential of its own, talking to the same public API. It is not a CLI and grows no CLI duties.
- **CLI**: transport for human and CI intent, plus **all client-local delivery machinery** (#18): render generations, stamps, snapshots, offline audit records, `run --` exec, `doctor` self-checks. The CLI holds client-side secrets (stamp/snapshot keys) that are *outside the server key hierarchy* (#22) — custody, not authority.
- **There is no agent.** #18 withdrew `--watch` and forbids the resident watcher; nothing here reintroduces one. Anything that looks like "the CLI staying resident" is either `run --` (which execs and ceases to exist) or does not exist.

## Residuals, stated

- **`--dangerously-print` is still a disclosure.** The triad makes accidental plaintext-to-CI-log hard, not impossible — a user who passes the flag in CI has published the value to their CI system's log retention. The flag's name is the mitigation; the audit event is the record; no further control exists and this ADR does not pretend one does.
- **The pin file directs, it never authorizes and never introduces trust.** With the trust-store rule, a hostile pin-file edit is bounded to retargeting *within origins this box already trusts and the caller's grants already reach*: the echo (ids + artifact) and per-key audit are the mitigations for that residue; the credential-exfiltration variant is closed by construction.
- **Loopback handoff on a shared/compromised box**: a local attacker who can win the loopback bind race before the CLI or read the state directory is inside #16/#22's stated client-compromise boundary; the code+PKCE construction stops callback interception from yielding a session, not local-root compromise.
- **Behavioural freeze rests on review.** Schema-level freeze is machine-checked; the authorization-formula and semantics freeze is enforced by human review of a hand-written spec — a process, stated as such. The contract tests narrow the gap (formulas surface as status/shape assertions) but do not close it.
- **Parity is a review discipline for CLI-first gaps.** UI-without-endpoint is impossible structurally; endpoint-without-UI is caught by the closed exemption-list review — a process, not a compiler. The prototypes (#29/#30/#31) carry it as an explicit criterion.
