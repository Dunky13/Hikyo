Validation

Broken config fails here, not at 3am

Every key carries a type, constraints and an optional JSON Schema. Required-but-unset and schema violations block the publish instead of the deploy.

Disclosure

Reading a secret is an event

Secrets are write-only by default. Revealing one is permission-gated, time-boxed, auto-remasked and written to the audit log, including the copy to your clipboard.

01 / ORIGIN

Four environments, one row, no diffing.

Base holds what is true everywhere. Each environment states only its disagreements. The row shows which of them won, and the arrow says where the rest came from, so an override is a decision you can see rather than one you discover.

02 / VALIDATION

The bad value never reaches the deploy.

Keys are declared before they are filled: type, constraints, required-in-which-environments, and JSON Schema when the shape matters. Publishing runs the whole set. A violation stops the publish, not the pod.

✕ publish refused · production
SMTP_PORT = "587 ", expected int, got string
STRIPE_WEBHOOK_SECRET, required in production, unset
2 violations · 84 keys checked · nothing was written
03 / DISCLOSURE

Writing a secret does not require reading it.

Rotation, seeding and correction all work write-only. Reveal is a separate, gated act: reauth, a fixed window, an automatic remask, and a line in the audit log. The clipboard counts as a disclosure too.

terminal
$ hikyo set DATABASE_URL --env prod --stdin
reading value from stdin, not echoed…
✓ wrote prod/DATABASE_URL (rev 30, write-only)

$ hikyo get DATABASE_URL --env prod
✕ refused: reveal in production requires reauth
  run: hikyo auth reveal --env prod   (window 60s)
04 / DELIVERY

Compose and Kubernetes are not an afterthought.

A workload gets a machine identity, not a copy of your .env. The operator reconciles a pinned revision into a Secret and reports what it did in conditions you can read with kubectl. No sidecar, no init-container hack.

Every key is declared before it is filled. SMTP_PORT is an

          space is a refused publish rather than a paged engineer.

          and hikyo tells you how many environments that is before you publish.
